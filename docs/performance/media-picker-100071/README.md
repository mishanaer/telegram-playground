# Производительность 100071 — 9 сентября 2026

Позднее выполнен [замер реально показанных кадров на физическом iPhone, Release 100073](../media-picker-100073/README.md). Приведённые ниже результаты симулятора остаются измерением callback cadence и напрямую с ним не сравниваются.

На симуляторе наблюдалась частота CADisplayLink около 60 вызовов/с. В сценарии открытия есть редкие задержки callback до 56 ms; утверждать стабильные 60 rendered FPS нельзя. GPU FPS не измерен.

Код опубликован: [c58ffa0c077fd06e19e364a6b2ab22769d0659ea](https://github.com/mishanaer/telegram-playground/commit/c58ffa0c077fd06e19e364a6b2ab22769d0659ea), ветка codex/quick-attach.

## Условия

- Telegram Playground: iPhone 17 Pro / iOS 27.
- Debug simulator build 100071, Mac Apple M4 Pro / macOS 26.5.1.
- 31 импортированный файл и 6 исходных медиа; перед измерением медиапикер открыт и прокручен.
- Два отдельных окна наблюдения примерно по 18 s. Прокрутка: два жеста scroll-up/down, delta 150, duration 4 s. Открытие: два открытия и закрытие между ними. Окна включают паузы и обновление UI-снимков автоматизацией; это не чистый замер только активной фазы анимации.
- Временный диагностический dylib загружен в процесс через LLDB; сборка приложения на диске не изменялась. Старт отложен до возобновления main runloop; на время наблюдения LLDB отсоединён. CADisplayLink с политикой частоты по умолчанию, без принудительного FPS. В callback только запись трёх timestamp в C-buffer, вывод файлов после измерения.

## Результаты

Это частота вызовов UI-наблюдателя, НЕ число фактически показанных кадров GPU/композитора.

| Сценарий | Окно | Callback/s | P95 интервала | P99 | Максимум | CPU процесса, 100%=одно ядро |
| --- | --- | --- | --- | --- | --- | --- |
| Прокрутка вверх/вниз | 18.25 s | 59.95 | 16.71 ms | 16.90 ms | 33.04 ms | 5.98% |
| Открытие/закрытие шторки | 18.13 s | 59.50 | 16.70 ms | 17.13 ms | 55.99 ms | 13.88% |

Медианный интервал в обоих случаях — 16.67 ms. При прокрутке один callback-интервал длиннее 25 ms, ни одного длиннее 33.4 ms. В сценарии открытия семь интервалов длиннее 25 ms, три длиннее 33.4 ms, один длиннее 50 ms. Источник этих редких задержек этим измерением не установлен.

CPU относится к процессу целиком, включая измеритель и запросы автоматизации, а не только warp. Пиковую загрузку CPU эти средние значения не показывают. CADisplayLink сам будит главный поток; наблюдатель не имеет нулевой стоимости и не обнаруживает все задержки GPU.

## Профиль CPU и память

Отдельно снят штатный Apple sample на 12 s при прокрутке. Из 8690 снимков главного потока 96.21% относятся к ожиданию RunLoop. Значительная часть остальных наблюдений связана с AXRuntime/UIAccessibility автоматизации. Пересчёт mesh не встретился в выборке; это не доказательство нулевой стоимости эффекта.

Physical footprint во время этого прогона — 177.4M, peak 182.0M. Idle sample ранее показал 159.6M. Это не RSS: сырые RSS-снимки диагностического процесса сохранены отдельно в summary JSON и включают другие категории памяти, поэтому напрямую с footprint не сравниваются.

Symbolicated sample использован как статистическая выборка стеков, не как CPU-процент или FPS.

## Ограничения и очистка

Animation Hitches и Time Profiler через xctrace на Simulator не завершили подключение и не выдали финализированный trace. Процессы этих попыток остановлены. Host-only Time Profiler не обнаружил simulator PID. Также отмечено, что macOS Developer mode отключён; причинная связь зависания с этим не доказана, настройка не менялась. Незавершённые .trace не использованы для выводов. Подключённого физического iPhone нет (устройство показывается offline).

Сравнимого performance baseline версии Claude не снято, поэтому ускорение в процентах не заявляется. Симулятор использует ресурсы Mac; эти числа не прогноз FPS на iPhone. В частности, callback/s нельзя переименовывать в rendered FPS.

После измерений приложение перезапущено без загруженного dylib, исходники и опубликованный коммит не изменены. Исходник измерителя сохранён рядом с отчётом; в приложение и его сборочные зависимости он не включён.

```sh
python3 analyze-callback-cadence.py --self-test

```
